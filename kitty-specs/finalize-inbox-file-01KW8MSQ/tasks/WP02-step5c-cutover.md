## Subtasks

### T007 — Add the exit-code handling table to Step 5c (FR-005)

**Purpose**: Tell the agent exactly what to do for each finalize exit code.

**Steps**: In Step 5c, immediately after the `mark_processed` invocation, add a
short table (Markdown) the agent must follow:

| Exit | Meaning | Agent action |
|------|---------|--------------|
| 0 | finalized (or already processed) | proceed; the note stays in `01-Inbox/` |
| 1 | validation failure (bad path / outside inbox root / bad frontmatter) | record the failure in the run summary; do NOT silently continue |
| 2 | filesystem error (perm denied / write race) | **surface/escalate** — this is the silent-failure class; the note is left `unprocessed`, uncorrupted |
| 3 | privacy refusal (`04-Growth/_private/`) | expected; skip, no escalation |

Phrase it as standing orders the LLM agent follows, consistent with the file's
existing voice. Reference that the helper prints a single-line JSON on stdout (exit
0) and an `{"error": …}` line on stderr for non-zero exits.

`02-Inbox-Processed/`. If the existing invariant text is already sufficient, tie it
