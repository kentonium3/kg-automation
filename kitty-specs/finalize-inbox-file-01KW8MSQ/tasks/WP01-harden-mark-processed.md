## Objective

Close the **silent-finalize-failure** class in the *existing*
`scripts/inbox/mark_processed.py`. The helper already performs the atomic,
mode-preserving, idempotent in-place `status: processed` + `processed_at` write and
already refuses `04-Growth/_private/` paths (exit 3). This WP adds the missing
orchestrator-facing robustness **without weakening any existing guarantee**:

1. **Exit 2 on filesystem error** — a write `OSError` (permission denied, write
   race) must become a clean exit 2 with the specific `OSError` on stderr, not an
   uncaught traceback. (FR-001 — the literal 2026-05-18 incident path.)
2. **Single-line JSON on stdout on success** — so the orchestrator can confirm a
   finalize without re-reading the note. (FR-002)
3. **Inbox-root validation** — `--path` must resolve under the registry inbox
   root; otherwise exit 1. (FR-003)
4. **Preserve everything else** — atomicity, idempotency, frontmatter/body
   round-trip, in-place (no move), and the exit-3 private refusal. (FR-004)

Final exit-code contract: **`0` success/idempotent · `1` validation · `2`
filesystem error · `3` private refusal**. Exit 2 is currently unused, so this is
additive — do **not** renumber the existing exit 3.

## Subtasks

### T001 — Inbox-root validation (FR-003)

**Purpose**: Reject a `--path` that does not live under the registry-resolved inbox
root, as a validation failure (exit 1), before any write.

**Steps**:
1. Import `resolve_registry` from `scripts.inbox.prescan` (lazy import inside the
   function is fine to avoid import cost / cycles).
2. Resolve the inbox root. `resolve_registry()` returns `(registry_path, inbox_dir)`
   (confirm by reading prescan); use the inbox dir.
3. Resolve the candidate path (`Path(args.path).resolve()`) and verify it is within
   the inbox root (`inbox_root in path.parents` or `path.is_relative_to(inbox_root)`
   on 3.9+). If not, print `{"error": "outside_inbox_root", "detail": "<path>"}` to
   **stderr** and return **1**.
4. Ordering: the private-path refusal (exit 3) still fires first in `main()` before
   any disk read. Inbox-root validation is part of the validation tier (exit 1) and
   should run before the write (it may run before or after the existence check, but
   keep all exit-1 validation together and emit one clear error).

**Validation**: a path outside the inbox root → exit 1 + `outside_inbox_root`
stderr JSON; a legitimate `01-Inbox/...` path proceeds.

**Edge cases**: symlinks (use `.resolve()` on both sides); the test override
(`PRESCAN_REGISTRY_PATH`) must make a tmp vault count as "inside root".

### T002 — Filesystem-error exit 2 (FR-001) — the core fix

**Purpose**: Convert a write `OSError` into a clean exit 2 with a structured stderr
signal, leaving the note uncorrupted.

**Steps**:
1. In `mark_processed()`, wrap the `_atomic_write(path, new_text)` call (and the
   `os.stat` mode read it performs) in `try/except OSError as exc`.
2. On `OSError`: print `{"error": "fs_error", "detail": "<repr or str of exc>"}` to
   **stderr** and `return 2`. Keep the detail single-line (no embedded newlines).
3. Confirm `_atomic_write` already unlinks its tempfile on failure (it does) so the
   original note is never left partial — do not change that primitive's behavior.
4. Do not catch `OSError` so broadly that you swallow the earlier `read_text`
   failure path (which is a validation/exit-1 concern) — scope the catch to the
   write.

**Validation**: a read-only (`0o444`) note → exit 2 + `fs_error` stderr JSON; the
note content is byte-for-byte unchanged afterward (NFR-003).

### T003 — Success JSON on stdout (FR-002, NFR-004)

**Purpose**: Emit one machine-readable line on stdout on every success, including
the idempotent no-op.

**Steps**:
1. Define the success payload:
   `{"finalized": true, "already_processed": <bool>, "status": "processed", "file_final_path": "<abs path of the note, unchanged>"}`.
2. On the idempotent path (`fm.get("status") == "processed"`): set
   `already_processed=true`, print the JSON, return 0 (no write).
3. On a real write success: set `already_processed=false`, print the JSON after the
   write, return 0.
4. Use `json.dumps(...)` (single line, default separators). Print to **stdout**.
   Keep the existing `INFO: atomic_write …` line on **stderr** — stdout stays a
   single clean line (NFR-004).
5. `file_final_path` is the in-place `01-Inbox/` path (no move ever).

**Validation**: happy path → exactly one stdout line, parseable, `finalized=true`,
`already_processed=false`; re-run → `already_processed=true`. stdout has no other
content.

### T004 — Preserve guarantees + docstring (FR-004)

**Purpose**: Make the additive nature explicit and keep the contract documented.

**Steps**:
1. Verify (by reading) that atomicity, idempotency, frontmatter key-order + body
   round-trip, and the exit-3 `_private/` refusal are unchanged.
2. Update the module docstring's exit-code table from `0/1/3` to **`0/1/2/3`**, add
   the `2 = filesystem error (perm denied / write race); stderr carries the OSError`
   line, and note the stdout success-JSON contract. Keep the `-m` invocation note.
3. Keep stdlib-only (NFR-001): `json` is stdlib — no new deps.

**Validation**: docstring reflects 0/1/2/3 + stdout JSON; no new imports beyond
stdlib (`json`).

### T005 — Extend the tests (FR-001..004; SC-004)

**Purpose**: Cover all five outcomes against the new contract in
`tests/inbox/test_mark_processed.py` (read it first; reuse its fixtures and the
`PRESCAN_REGISTRY_PATH` hermetic-vault pattern).

**Add tests**:
1. **exit 2, perm-denied + uncorrupted**: write a tmp note in a tmp inbox vault,
   `os.chmod(note, 0o444)`, run `main(["--path", str(note)])`, assert returns 2,
   stderr has `fs_error`, and the note bytes are unchanged. **Skip-guard when
   `os.geteuid() == 0`** (root bypasses mode bits) — `pytest.mark.skipif`.

3. **exit 1, outside inbox root**: a path outside the tmp inbox root → exit 1 +
   `outside_inbox_root`.
4. **stdout JSON**: happy path → capture stdout, `json.loads` one line, assert
   `finalized=true, already_processed=false, status=processed`, path unchanged;
   idempotent re-run → `already_processed=true`.
5. Keep/confirm existing tests for happy write, idempotent no-op, missing file
   (exit 1), no-frontmatter (exit 1), and `_private/` refusal (exit 3) still pass.

**Validation**: new tests fail against the unmodified helper and pass after T001–T004.
