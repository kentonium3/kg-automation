## Subtask T002 — Create `schedule_loader.py` [P]

**Purpose**: A single, typed entry point that loads `phase3-schedule.yaml` and returns a list of habit entries with their day-of-week metadata. Both `query_active_habits_v2.py` (in this WP) and `sweeper.py` (in WP-02) will consume this.

**Steps**:
1. Create `scripts/habits/schedule_loader.py`:
   - `WEEKDAY_NAMES = ("Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun")` constant (in ISO weekday order: Mon=0).
   - `ScheduleEntry` dataclass: `task_id: int`, `title: str`, `designated_weekdays: tuple[str, ...]` (empty tuple = daily), `repeat_after_seconds: int`, plus any other existing fields that callers need (read the existing YAML to enumerate). Keep the dataclass focused on what consumers need — don't over-engineer.
   - `load_schedule(path: Path) -> list[ScheduleEntry]`:
     - Reads + parses YAML.
     - Validates each entry: `designated_weekdays` if present must be a list of three-letter strings, each in `WEEKDAY_NAMES`. Unknown values raise `ScheduleConfigError` (load-time error).
     - Dedupes `designated_weekdays` silently (a habit listed for `["Wed", "Wed"]` becomes `("Wed",)`).
     - Returns a list of `ScheduleEntry` instances.
   - `is_day_specific(entry: ScheduleEntry) -> bool`: returns `True` iff `len(entry.designated_weekdays) > 0`.
   - `is_active_today(entry: ScheduleEntry, today_weekday: str) -> bool`: returns `True` if entry is daily OR if `today_weekday in entry.designated_weekdays`. The `today_weekday` arg is a 3-letter string like `"Wed"` — caller computes it from `compute_today.py`.
   - Define `ScheduleConfigError(Exception)` for all load-time failures.
2. Add a module docstring explaining the file's role (central loader, consumed by morning_checkin_list and sweeper).
3. Keep the module under ~120 lines.

**Files**:
- `scripts/habits/schedule_loader.py` (new, ~120 lines)

**Validation**: covered by T006.

**Purpose**: Modify `query_active_habits_v2.py` so the returned active-habit list excludes day-specific habits whose designated weekdays don't include today (ET).

**Steps**:
1. Read the current `query_active_habits_v2.py` to understand:
   - The exact API surface (function signatures, return shape).
   - How `today_date` is currently passed in or computed.
   - What data the Vikunja query returns per habit (the consumer needs to be able to map task_id → ScheduleEntry).
2. Extend the public query function (likely `query_active_today` per the existing module docstring) to accept an optional `schedule_loader` parameter — or to internally load the schedule via `from .schedule_loader import load_schedule, is_active_today`. The simpler approach (internal load) is preferred; the optional-param approach is the test-friendly fallback.
3. After the existing Vikunja query produces the candidate list, apply the day-of-week filter:
   - For each candidate task, look up its `ScheduleEntry` (by task_id).
   - If found AND `is_active_today(entry, today_weekday)` is False, EXCLUDE.
   - If NOT found in the schedule (e.g., a habit in Vikunja not in the YAML): include by default (daily fallback). Log a warning to stderr noting the un-scheduled habit.
4. Today's weekday is computed from the existing `compute_today.py` (or its output is already an arg to the query function — preserve existing call pattern).
5. Preserve all existing test behavior: tests that don't supply day-specific entries in their fixture schedules MUST still see all returned habits (default daily fallback).

## Subtask T005 — Add `--reconcile-schedule` flag to `set_due_dates.py` [P]

**Purpose**: Operator-invokable command that reads the (newly-updated) `phase3-schedule.yaml` and, for each habit whose `designated_weekdays` changed since the last reconciliation, advances its Vikunja `due_date` to the next occurrence of the new designated weekday. Writes a structured reconciliation record per data-model E5.

**Steps**:
1. Read the existing `scripts/habits/set_due_dates.py` to understand:
   - Argparse structure.
   - Vikunja PUT helper.
   - Per-habit-failure resilience pattern.
   - Output JSON + `SUMMARY:` line format.
2. Add a new `--reconcile-schedule` flag (mutually exclusive with the existing `--iso-eod-et` mode). When set:
   - Loads the schedule via `schedule_loader.load_schedule`.
   - For each entry with `designated_weekdays` populated:
     - Query Vikunja for the habit's current `due_date`.
     - Compute the expected `due_date` = next occurrence of designated weekday from today at end-of-ET-day (use `compute_today.py` for today; use a small helper for the next-weekday math — refer to `migrate_schedule.py:516` for the existing pattern).
     - If current ≠ expected, PUT the new due_date. Otherwise no-op (idempotent).
   - Write a reconciliation record per E5 to `/data/services/openclaw/state/habits/reconcile-<ISO-UTC-timestamp>.json` (atomic write via tempfile + rename).
   - Output JSON to stdout: `{"reconciled": [{task_id, old_due_date, new_due_date}], "skipped_no_change": [task_id, ...], "errors": [...]}`.
   - `SUMMARY:` line: `SUMMARY: reconciled=<n> skipped=<n> errors=<n>`.
3. Reuse the existing `--iso-eod-et` validation regex (`ISO_EOD_PATTERN`) to ensure the computed new_due_date passes the `Z`-suffix check (issue #112 regression-prevention).
4. Exit codes: 0 = success, 1 = at least one per-habit failure, 2 = usage error.

**Files**:
- `scripts/habits/set_due_dates.py` (modified, ~60-80 lines added)
