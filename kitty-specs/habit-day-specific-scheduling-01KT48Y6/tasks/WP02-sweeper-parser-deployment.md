## Subtask T008 — New `sweeper.py`

**Purpose**: The entrypoint for the daily 48hr auto-skip sweep. Reads recent morning-checkin artifacts + habits-history.jsonl, identifies habit instances >48hr old that haven't been resolved, appends `auto_skipped` events, and (for day-specific habits) advances Vikunja `due_date` to next designated weekday.

**Steps**:
1. Create `scripts/habits/sweeper.py`:
   - Imports: `from .schedule_loader import load_schedule, is_day_specific` (cross-WP import — WP-01 deliverable).
   - `SweeperTickRecord` dataclass matching `data-model.md` §E4.
   - `find_expired_checkins(state_dir, now_utc) -> list[CheckinArtifact]`: returns morning-checkin-<date>.json artifacts whose `delivered_at_utc` is >48hr ago AND >24hr ago (the lower bound prevents accidentally re-evaluating today's). Conservative cutoff per OD-2.
   - `evaluate_habit_resolution(history, task_id, checkin_date_et) -> str`: scans habits-history.jsonl for events targeting this habit instance. Returns one of: `"completed_in_window"`, `"skipped_in_window"`, `"already_auto_skipped"`, `"unresolved"`.
   - `compute_next_designated_weekday_et(designated_weekdays, today_weekday_index, now_et) -> datetime`: pure-function helper. Returns the next occurrence of the nearest-future designated weekday at EOD-ET.
   - `run_sweep(config, schedule_path, state_dir, history_path, vikunja_token_path, vikunja_base_url, now_utc, dry_run=False) -> int`:
     - Generate `tick_id` via ULID.
     - Load schedule via `schedule_loader.load_schedule`.
     - Find expired check-ins.
     - For each expired check-in's habit entries: evaluate resolution. For unresolved:
       - Check idempotency: scan history.jsonl for an existing `auto_skipped` event matching `(task_id, original_checkin_date_et)`. If found, mark as `already_auto_skipped`, skip.
       - Otherwise, append `auto_skipped` event to history.jsonl (atomic — use file locking or single-append-then-fsync).
       - If habit is day-specific: compute new due_date via `compute_next_designated_weekday_et` and PUT to Vikunja (skip in dry-run).
     - Write `sweeper-tick-<date>.json` atomically per E4.
     - Append the tick record to `sweeper-ledger.jsonl`.
     - Print `SUMMARY:` line.
     - Return 0 on success, 1 on partial failure.
   - `main()` argparse: `--state-dir`, `--history-path`, `--schedule-path`, `--vikunja-token-path`, `--vikunja-base-url`, `--dry-run`, `--now-utc <ISO-8601>` (for testing).
2. Issue #112 regression-prevention: any new due_date computed by `compute_next_designated_weekday_et` MUST end with explicit `-04:00` or `-05:00` (NOT `Z`). Add a load-time assertion + tests.
3. Per-habit-failure resilience: continue on per-habit error, accumulate `errors[]` in the tick record, exit 1 if any errors but tick ran to completion.
4. Keep the sweeper under ~300 lines.

**Files**:
- `scripts/habits/sweeper.py` (new, ~300 lines)

**Validation**: covered by T013.

## Subtask T010 — Systemd unit files [P]

**Purpose**: Author the systemd user units that fire the sweeper daily at 7:30 AM ET.

**Steps**:
1. Create `scripts/office2/felix-habit-sweeper.service`:
   ```ini
   [Unit]
   Description=Felix Habit Sweeper — 48hr auto-skip pass (mission #408)
   After=network-online.target
   Wants=network-online.target

   [Service]
   Type=oneshot
   ExecStart=/usr/bin/python3 /home/claude/kg-automation/scripts/habits/sweeper.py
   Environment=HOME=/home/claude
   WorkingDirectory=/home/claude/kg-automation
   ```
   - Use `/usr/bin/python3` IF PyYAML is available system-wide (verify during deploy). If not, switch to a dedicated venv path per the mission #59 precedent.
   - Path MUST be `/home/claude/kg-automation/...` (NOT `/repos/`) — see the #59 cutover lesson at the runbook precedent.
2. Create `scripts/office2/felix-habit-sweeper.timer`:
   ```ini
   [Unit]
   Description=Felix Habit Sweeper — daily at 07:30 America/New_York

   [Timer]
   OnCalendar=*-*-* 07:30:00 America/New_York
   Persistent=true

   [Install]
   WantedBy=timers.target
   ```
   - `OnCalendar` with `America/New_York` timezone fires at 7:30 AM local ET, automatically adjusting for DST.
   - `Persistent=true` ensures a missed tick (office2 was offline at 7:30) runs once on next start.
3. Verify with `systemd-analyze --user verify` post-deploy (deferred to T012's cutover procedure).
