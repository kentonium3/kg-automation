# WP01 — Google Workspace foundation docs and architecture state

## Objective

Deliver the operator runbook and architecture-state updates that complete the Google Workspace integration foundation. Builds on ADR-0001 (committed `a0a7660`) and the live setup work that landed Linuxbrew + gog + the OAuth chain on 2026-05-13.

**Pure docs/architecture mission.** No new code. No new tests beyond `validate_docs.py`. No agent prompt changes.

**Review scope (WP01)**: T001–T007 — runbook + 4 architecture-state updates + legacy archive + INDEX/map registration + validate_docs. Post-merge operator regression smoke tests are out of scope per the rescope discipline (prior missions' pattern).

## Context

ADR-0001 selected `gog` CLI via Linuxbrew for Google Workspace integration. The decision is grounded in: the video transcript walkthrough, the live verification that all six target services authenticate end-to-end (Calendar, Gmail, Drive, Contacts validated by live API calls 2026-05-13; Sheets and Docs validated transitively via shared refresh token + confirmed API enablement).

The live setup chain surfaced three non-obvious failure modes that this mission's runbook must document load-bearingly:

1. **Calendar MCP API trap**: When Kent searched "Calendar" in the Google Cloud API library, the new "Calendar MCP API" surfaced and he enabled it thinking that was the right one. The actual Google Calendar API was not enabled until the smoke test failed with "Google Calendar API has not been used in project ... before or it is disabled" and we followed the error message's link.
2. **D-Bus SecretService failure on headless server**: gog's default keyring backend timed out trying to reach D-Bus SecretService (which doesn't run on headless Ubuntu). OAuth completed but the refresh token couldn't be stored. The fix was setting `GOG_KEYRING_BACKEND=file` and `GOG_KEYRING_PASSWORD=<passphrase>` env vars before re-running the OAuth flow (the OAuth code is single-use, so the operator restarts from `gog auth add` step 1).
3. **Per-user brew PATH**: Linuxbrew's installer added `eval "$(/home/linuxbrew/.linuxbrew/bin/brew shellenv)"` to kgale's `~/.bashrc` only. claude's `~/.bashrc` needed the same line separately. Without it, fresh ssh sessions for claude hit `gog: command not found`.

See [spec.md](../spec.md), [plan.md](../plan.md), [research.md](../research.md), and [quickstart.md](../quickstart.md) for full context.

### T001 — Add `docs/runbooks/google-workspace-ops.md`

**Purpose**: Self-contained operator runbook covering the full setup procedure.

**Sections** (load-bearing structure):

1. **Overview** — what gog is, what it provides, which Google services it covers, who runs it (claude on office2), what other Felix agents will consume it (downstream user-story missions).
2. **One-time setup procedure**:
   1. Install Linuxbrew on office2 (as kgale, with sudo). Three single-line commands: apt install build-essential procps curl file git, the brew install script, the bashrc shellenv eval.
   2. Install gog: `brew install steipete/tap/gogcli`.
   3. Persist brew in claude's bashrc: `echo 'eval "$(/home/linuxbrew/.linuxbrew/bin/brew shellenv)"' >> ~/.bashrc`.
   4. Set up Google Cloud Console: create project, enable Gmail/Calendar/Drive/People/Sheets/Docs APIs (NOT Calendar MCP — see pitfall 1), OAuth consent screen (External, add test user), Credentials → Create Credentials → OAuth Client ID (Desktop app type), download `client_secret.json`.
   5. scp client_secret.json to office2: `scp /Users/kentgale/Downloads/client_secret_*.json office2-claude:/data/services/openclaw/secrets/google-workspace-client.json && ssh office2-claude 'chmod 600 /data/services/openclaw/secrets/google-workspace-client.json'`.
   6. Set up gog keyring file backend (headless workaround per pitfall 2):
      - `openssl rand -base64 32 > /data/services/openclaw/secrets/gog-keyring-password && chmod 600 ...`
      - Append two env-var exports to claude's `~/.bashrc`: `GOG_KEYRING_BACKEND=file` and `GOG_KEYRING_PASSWORD="$(cat /data/services/openclaw/secrets/gog-keyring-password)"`.
   7. Ingest credentials: `gog auth credentials /data/services/openclaw/secrets/google-workspace-client.json`.
   8. Run the OAuth two-step `--remote` flow:
      - Step 1: `gog auth add <email> --services gmail,calendar,drive,contacts,docs,sheets --remote` → prints auth URL.
      - Open URL in Mac browser → Advanced → Continue → Select all scopes → Continue → browser fails on redirect (expected).
      - Copy the full localhost callback URL.
      - Step 2: capture URL via `read -r REDIRECT_URL` to avoid paste-mangling, then `gog auth add <email> --remote --step 2 --auth-url "$REDIRECT_URL" --services gmail,calendar,drive,contacts,docs,sheets`.
   9. Verify: `gog auth list` shows the account with all 6 scopes.
   10. Smoke-test live API: `gog calendar colors`, `gog gmail search 'newer_than:1d' --max 1`, `gog drive search "x" --max 1`, `gog contacts list --max 1`.
3. **Common pitfalls** — load-bearing per NFR-002. Each pitfall has: symptom (exact error message operator sees), root cause (one-sentence), fix (one command or one console action).
   - **Pitfall 1: Calendar MCP API in API library search**.
     - Symptom: `gog calendar colors` returns `Google API error (403 accessNotConfigured): Google Calendar API has not been used in project ... before or it is disabled.`
     - Root cause: API library search for "Calendar" returns "Calendar MCP API" (a newer agent-protocol API) before the classic "Google Calendar API". Operator enables the MCP one thinking it's the right one.
     - Fix: open the URL the error provides (or navigate APIs & Services → Library → search "Google Calendar" — the full string with "Google" prefix surfaces the right one). Enable it. Wait ~30s for propagation. Retry.
   - **Pitfall 2: D-Bus SecretService failure (headless keyring)**.
     - Symptom: `gog auth add ... --remote --step 2 ...` returns `OAuth completed, but saving the refresh token failed: store token: keyring connection timed out after 10s while storing keyring item (D-Bus SecretService may be unresponsive); set GOG_KEYRING_BACKEND=file and GOG_KEYRING_PASSWORD=<password> to use encrypted file storage instead`.
     - Root cause: D-Bus SecretService is a desktop-environment service. Headless Ubuntu servers don't run it.
     - Fix: see step 6 of the setup procedure. Note that the OAuth code is single-use, so after setting the env vars the operator must restart from `gog auth add` step 1 (fresh URL → fresh consent → fresh redirect URL → fresh step 2 invocation).
   - **Pitfall 3: Per-user brew PATH**.
     - Symptom: as the claude user (fresh ssh session, did NOT install brew themselves), `gog auth ...` returns `Command 'gog' not found, but there are 16 similar ones.`
     - Root cause: Linuxbrew installer updates only the installing user's `~/.bashrc` with the brew shellenv line. claude's `~/.bashrc` doesn't have it because kgale ran the installer.
     - Fix: as claude, `echo 'eval "$(/home/linuxbrew/.linuxbrew/bin/brew shellenv)"' >> ~/.bashrc && source ~/.bashrc`. (For the current session only, `eval "$(/home/linuxbrew/.linuxbrew/bin/brew shellenv)"` is sufficient; the bashrc append is for future sessions.)
4. **Common commands** — Gmail search, Calendar list/create/update, Drive search, Contacts list, Sheets get/update/append, Docs cat/export. Copy directly from `/usr/lib/node_modules/openclaw/skills/gog/SKILL.md` on office2 (gog's bundled instruction file). Link to gog homepage for full reference.
5. **Adding a second Google account (Intentional business)** — same Cloud Console procedure against the Intentional account → separate Client ID → scp the new client_secret.json with a distinct filename → `gog auth credentials --client intentional <path>` (or similar alias depending on gog flag spelling — verify with `gog auth add --help` at the time) → `gog auth add intentional@example.com --client intentional --services gmail,calendar,drive,contacts,docs,sheets --remote` → verify `gog auth list` shows both accounts.
6. **Health checks / troubleshooting** — `gog auth doctor`, `gog auth list`, `gog auth status`, `openclaw skills info gog`, checking refresh token expiry, expanding scopes (re-run `gog auth add` with broader `--services`).
7. **References** — ADR-0001, gog homepage (https://gogcli.sh), SKILL.md location on office2.
