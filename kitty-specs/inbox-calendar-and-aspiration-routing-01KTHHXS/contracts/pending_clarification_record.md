# Contract: PendingClarificationRecord JSONL line

**Mission**: `inbox-calendar-and-aspiration-routing-01KTHHXS`
**Spec FR**: FR-007 | **Data model**: [`PendingClarificationRecord`](../data-model.md#entity-pendingclarificationrecord-persistent-jsonl)

## Purpose

Defines the line-level shape of the state file at `~/second-brain/agents/state/pending-calendar-clarifications.jsonl`. Each line is a complete JSON object (newline-delimited JSON convention). This file is the load-bearing substrate for the calendar-event clarification reply UX.

## File location and conventions

- **Absolute path**: `~/second-brain/agents/state/pending-calendar-clarifications.jsonl`
- **Format**: newline-delimited JSON (JSONL). One JSON object per line, no trailing comma, no enclosing array.
- **Encoding**: UTF-8.
- **Line ending**: `\n` (Unix).
- **Ordering**: append-only on add; rewrite-with-filter on resolve. Order within the file is insertion order — but consumers MUST NOT rely on this; match by `clarification_id`.
- **Concurrent access**: file lock via `fcntl.flock` (LOCK_EX) for any read-modify-write operation. Single-writer at a time. Read-only reads do not need a lock (eventual-consistency reads are fine for diagnostics).

## Line schema

```json
{
  "clarification_id": "01KTHHXSAP609CQYPJ490ABCDEF",
  "source_inbox_path": "/home/kgale/second-brain/notes/01-Inbox/Inbox 2026-06-08 0930.md",
  "source_block_index": 0,
  "fields_so_far": {
    "title": "Lunch with John",
    "start_natural": "next Tuesday",
    "end_natural": null,
    "duration_natural": null,
    "location": null,
    "recurrence_natural": null,
    "attendees": null
  },
  "missing_fields": ["end_or_duration"],
  "sent_at": "2026-06-08T13:35:00-04:00",
  "last_reprompt_at": null,
  "resolved_at": null,
  "timed_out_at": null
}
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `clarification_id` | string (ULID) | yes | Generated by capture at record creation. 26 characters, base32 Crockford. |
| `source_inbox_path` | string | yes | Absolute path. |
| `source_block_index` | int | yes | Zero-indexed. |
| `fields_so_far` | object | yes | Echo of the partial `ExtractedCalendarBlock`. Schema matches that entity. |
| `missing_fields` | string[] | yes | Tokens from validator output: `start_datetime`, `end_or_duration`, `recurrence_pattern`, `title`. |
| `sent_at` | string (ISO 8601) | yes | When the WhatsApp prompt was sent. |
| `last_reprompt_at` | string (ISO 8601) \| null | optional | Updated if a follow-up prompt was sent (e.g., after a partial reply). |
| `resolved_at` | string (ISO 8601) \| null | optional | Set briefly during resolve before the line is removed. Diagnostic only — operational records have this null. |
| `timed_out_at` | string (ISO 8601) \| null | optional | Set when sweep flips the source note to needs-review. After this, the record is retained for audit. |

## Operations

### Append open record

```python
# capture pseudocode
record = build_record(...)  # clarification_id, source_inbox_path, fields_so_far, missing_fields, sent_at
with file_lock_excl(STATE_FILE):
    with open(STATE_FILE, "ab") as f:
        f.write(json.dumps(record).encode("utf-8"))
        f.write(b"\n")
        f.flush()
        os.fsync(f.fileno())
```

### Read all open records

```python
# any consumer
with open(STATE_FILE, "rb") as f:
    lines = f.read().decode("utf-8").splitlines()
records = [json.loads(line) for line in lines if line.strip()]
open_records = [r for r in records if r.get("timed_out_at") is None and r.get("resolved_at") is None]
```

### Resolve one record (remove)

```python
# Felix main pseudocode
with file_lock_excl(STATE_FILE):
    records = read_all()
    kept = [r for r in records if r["clarification_id"] != target_id]
    atomic_rewrite(STATE_FILE, "\n".join(json.dumps(r) for r in kept) + "\n")
```

### Mark timed-out (retain)

```python
# capture's sweep pseudocode
now = tick_iso
with file_lock_excl(STATE_FILE):
    records = read_all()
    changed = False
    for r in records:
        if r.get("timed_out_at") is None and \
           r.get("resolved_at") is None and \
           (now - parse_iso(r["sent_at"])) > 86400:
            r["timed_out_at"] = now
            changed = True
            # also flip source note frontmatter to status: needs-review
            flip_source_note_status(r["source_inbox_path"])
            log_action("calendar_event_clarification_timeout", ...)
    if changed:
        atomic_rewrite(STATE_FILE, "\n".join(json.dumps(r) for r in records) + "\n")
```

## Validation invariants

1. **Idempotent timeout sweep**: running the sweep N times produces identical state. The `timed_out_at` field prevents re-marking.
2. **Resolve-before-timeout**: if Kent's reply arrives in the same cron tick as the timeout, resolve wins (Felix main's resolve runs in-line on the inbound message; the sweep runs at the next capture tick).
3. **clarification_id uniqueness**: guaranteed by ULID monotonicity at generation time. No collision handling needed.

## What this file is NOT

- It is NOT a queue. Order doesn't drive processing — `clarification_id` matching does.
- It is NOT a permanent event log — successful resolutions are removed. The audit trail lives in `log_action` events, not in this file.
- It is NOT a Vikunja substitute. No task semantics here; this is workflow state for an in-progress clarification, nothing more.

## Why this contract exists

- A free-form state file silently grows or diverges across the capture+Felix-main boundary. The contract pins the line shape so both agents (and any future audit tool) read the same thing.
- The timeout + audit trail behavior is easy to mis-implement; documenting the rules here makes them reviewable.
