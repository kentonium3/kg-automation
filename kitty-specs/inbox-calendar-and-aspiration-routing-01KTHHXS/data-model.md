# Phase 1 Data Model: Inbox calendar and aspiration routing

**Mission**: `inbox-calendar-and-aspiration-routing-01KTHHXS`
**Spec**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Research**: [research.md](./research.md)

This document captures the entities, their fields, validation rules, and lifecycle transitions for the data crossing component boundaries in this mission. Entities described here either already exist (extended) or are new (defined fully).

---

## Entity: ExtractedCalendarBlock (transient, in capture)

In-memory payload produced by the capture LLM after classifying a block as calendar event. Lives until either (a) the validator+delegation chain consumes it, or (b) classification is rolled back.

| Field | Type | Required | Source | Notes |
|---|---|---|---|---|
| `title` | string | yes | LLM extraction | Event summary. Cleaned per existing voice-dump conventions. |
| `start_natural` | string | yes | LLM extraction | Original natural-language start phrase ("Tuesday 6pm", "next Friday at 2"). Helper validator parses this. |
| `end_natural` | string\|null | optional | LLM extraction | If LLM extracted explicit end. |
| `duration_natural` | string\|null | optional | LLM extraction | If LLM extracted duration ("1 hour", "30 minutes"). At least one of end_natural OR duration_natural must be present for completeness. |
| `location` | string\|null | optional | LLM extraction | Verbatim location string. |
| `recurrence_natural` | string\|null | optional | LLM extraction | Recurrence phrase ("every Tuesday", "biweekly"). |
| `attendees` | string[]\|null | optional | LLM extraction | List of emails/names. Free-text; gog handles invitation policy. |
| `source_inbox_path` | string | yes | Capture runtime | Absolute path to source inbox note. |
| `source_block_index` | int | yes | Capture runtime | Zero-indexed position of this block within the source note. |

**Validation rules** (applied by helper script — see contracts/validate_calendar_event.md):
- `title` non-empty
- `start_natural` parses to a valid datetime (helper attempts; if parse fails → missing)
- At least one of `end_natural` or `duration_natural` resolves to a valid end datetime
- If `recurrence_natural` present, must match one of the four supported patterns (per R-007); else "missing recurrence"

**Lifecycle**:
1. Created by capture's classification step.
2. Passed to `validate_calendar_event.py` via stdin.
3. Either → `CalendarEventPayload` (complete) or `MissingFieldsReport` (incomplete).
4. Discarded after either delegation succeeds or the source note flips to `needs-review`.

## Entity: CalendarEventPayload (transient, capture → Felix main)

Structured payload sent from capture to Felix main via `openclaw agent --agent main` when a calendar event is complete and ready to write.

| Field | Type | Required | Notes |
|---|---|---|---|
| `action` | string | yes | Always `"create_calendar_event"` to differentiate from other Felix-main message intents. |
| `calendar_id` | string | yes | Default `"primary"` per R-006. |
| `account` | string | yes | Default `"kent@intentional.biz"` per R-006. |
| `summary` | string | yes | Event title (was `title`). |
| `start_rfc3339` | string | yes | ISO 8601 / RFC 3339 start datetime with timezone. |
| `end_rfc3339` | string | yes | ISO 8601 / RFC 3339 end datetime with timezone. |
| `start_timezone` | string\|null | optional | IANA TZ (e.g., `"America/New_York"`). |
| `location` | string\|null | optional | Verbatim location. |
| `description` | string\|null | optional | Auto-generated: `Source: <inbox-note-basename>`. |
| `rrule` | string\|null | optional | RFC 5545 RRULE string when recurrence present. |
| `attendees` | string[]\|null | optional | |
| `source_inbox_path` | string | yes | For Felix main's audit logging. |
| `clarification_id` | string\|null | optional | Present only when this payload is the resolution of a pending clarification; null on first-pass success. |

**Validation rules**: All required fields present, start_rfc3339 < end_rfc3339, account matches one of the OAuth-authorized accounts.

**Lifecycle**:
1. Built by capture immediately after the validator returns `complete: true`.
2. JSON-encoded; passed via `--message '<json>'` to `openclaw agent`.
3. Felix main reads the action field, executes `gog calendar create`, returns result JSON.
4. Capture logs the outcome via `log_action`.

## Entity: PendingClarificationRecord (persistent JSONL)

State-file entity. One line per open incomplete calendar event. Persisted at `~/second-brain/agents/state/pending-calendar-clarifications.jsonl`.

| Field | Type | Required | Notes |
|---|---|---|---|
| `clarification_id` | string | yes | ULID. Generated by capture at creation time. |
| `source_inbox_path` | string | yes | Absolute path to inbox note. |
| `source_block_index` | int | yes | Zero-indexed block position. |
| `fields_so_far` | object | yes | Partial `ExtractedCalendarBlock` fields the LLM did extract. |
| `missing_fields` | string[] | yes | Array of field names still needed ("start_datetime", "end_or_duration", "recurrence_pattern"). |
| `sent_at` | string (ISO 8601) | yes | When the WhatsApp prompt was sent. |
| `last_reprompt_at` | string (ISO 8601)\|null | optional | If repeated prompts occurred. |
| `resolved_at` | string (ISO 8601)\|null | optional | Set when Felix main resolves; record removed shortly after. |
| `timed_out_at` | string (ISO 8601)\|null | optional | Set when 24h timeout fires. Record kept for audit. |

**Lifecycle (state machine)**:
```
              capture: incomplete event detected
                            │
                            ▼
                       [OPEN] ── sent_at recorded ─┐
                          │                         │
            Kent replies  │                         │ 24h elapsed without reply
                          ▼                         ▼
                  [RESOLVING]                   [TIMED_OUT]
                          │                         │
       Felix main creates │                         │ source note → status: needs-review
           event via gog  │                         │ `calendar_event_clarification_timeout` logged
                          ▼                         │
                  [RESOLVED] ── record removed       └─→ record kept for audit
```

**File operations** (atomic per spec NFR-004 idempotency):
- **Add open record**: capture builds the record, appends a JSON line to the file via atomic write (write to `.tmp`, fsync, rename).
- **Resolve**: Felix main reads all lines, filters out the matched clarification_id, writes back atomically. Then logs `calendar_event_clarification_resolved`.
- **Timeout sweep**: a separate sweep (cron tick on capture) reads all open records, marks any with `sent_at` >24h old as timed-out, updates the source note's frontmatter to `status: needs-review`, leaves the record in the file for audit.

## Entity: AspirationJournalEntry (transient, in capture)

Block-to-journal mapping. Not persisted as a discrete entity — the entry's content is appended directly to a dated journal file.

| Field | Type | Required | Notes |
|---|---|---|---|
| `cleaned_text` | string | yes | LLM-cleaned voice-dump content (per existing capture conventions). |
| `source_inbox_path` | string | yes | For source: reference in the journal entry. |
| `journal_target_path` | string | yes | Computed: `~/second-brain/notes/08-Journal/Journal YYYY-MM-DD HHmm.md` (HHmm = capture tick time). |

**Lifecycle**: built at classification time → appended to `journal_target_path` (creating the file if absent) → `log_action` records `journal_entry_appended`.

## Entity: SomedayTaskRequest (transient, in capture)

Vikunja task creation payload for Someday-classified blocks. Uses the existing vikunja-api skill's task-creation contract.

| Field | Type | Required | Notes |
|---|---|---|---|
| `project_id` | int | yes | Always `4` (resolved by name "Someday"). |
| `title` | string | yes | Concise task title from LLM. |
| `description` | string | yes | `Source: Inbox YYYY-MM-DD HHmm.md — [brief context]`. |
| `identity_label` | string | yes | Inferred per existing capture rules: personal / intentional / metalcasework. |
| `due_date` | null | always null | Someday tasks NEVER have a due date per FR-009. |

**Validation**: project_id resolves to a real project (name-based resolution at creation time, fallback to id=4 if name lookup fails for some reason — log a warning).

**Lifecycle**: built at classification time → vikunja-api skill POST `/projects/4/tasks` → log_action `someday_task_created` with task_id.

## Entity: RoutingLogEntry (EXISTING, extended)

Existing JSONL entity at `~/second-brain/agents/state/inbox-routing.jsonl`. Extended only by widening the implicit destination type vocabulary. Existing fields preserved.

Existing fields (per `append_routing_entry.py`):
- `note_basename`, `issue_number`, `task_id`, `excerpt`, `timestamp`, `agent`.

This mission extends the implicit `task_id` semantics: a Someday task's id can appear here; a journal append produces `task_id=-` (no task); a calendar event produces `task_id=-` with the calendar event ID captured in `log_action` context instead.

## Entity: LogActionEvent (EXISTING, extended)

Existing observability stream at `~/second-brain/agents/logs/observation/*.jsonl` (per `log_action.py`). Extended with new action types:

| Action type | Category | Context fields |
|---|---|---|
| `calendar_event_created` | routine | source_file, gcal_event_id, account, calendar_id, rrule |
| `calendar_event_failed` | error | source_file, error_detail |
| `calendar_event_clarification_sent` | routine | source_file, clarification_id, missing_fields |
| `calendar_event_clarification_resolved` | routine | source_file, clarification_id, gcal_event_id |
| `calendar_event_clarification_timeout` | flagged | source_file, clarification_id, sent_at |
| `journal_entry_appended` | routine | source_file, journal_target_path |
| `someday_task_created` | routine | source_file, vikunja_task_id |

## Relationship diagram (textual)

```
Inbox note (existing)
  │
  └─→ Capture LLM (classify block)
        │
        ├─→ Calendar event (complete) ──→ ExtractedCalendarBlock
        │                                       │
        │                                       └─→ validator helper ──→ CalendarEventPayload ──→ Felix main ──→ gog calendar create
        │                                                                                                          │
        │                                                                                                          └─→ LogActionEvent (calendar_event_created)
        │
        ├─→ Calendar event (incomplete) ──→ ExtractedCalendarBlock (partial)
        │                                       │
        │                                       └─→ PendingClarificationRecord (state file)
        │                                              │
        │                                              ├─→ Kent's WhatsApp reply ──→ Felix main matches + resolves
        │                                              │
        │                                              └─→ 24h timeout ──→ status: needs-review
        │
        ├─→ Aspiration ──→ AspirationJournalEntry ──→ 08-Journal/ append ──→ LogActionEvent (journal_entry_appended)
        │
        ├─→ Someday item ──→ SomedayTaskRequest ──→ Vikunja project 4 ──→ LogActionEvent (someday_task_created)
        │
        └─→ Active task (only after tightened rule) ──→ existing vikunja-api flow (unchanged)

All paths emit RoutingLogEntry to inbox-routing.jsonl after success.
```

## Validation invariants (cross-entity)

1. **Calendar events never produce Vikunja tasks**: enforced by classifier separation + capture code path divergence at the routing-table dispatch.
2. **Aspirations never produce Vikunja tasks**: same — classifier emits one of {calendar, aspiration, someday, active-task, goal, github-issue, reference}, dispatch is mutually exclusive.
3. **A PendingClarificationRecord exists ⟺ the source note has `status: needs-review` with no `processed_at`**: capture sets these together; Felix main clears them together on resolve.
4. **Re-processing same inbox file**: routing log entry's `note_basename` dedup prevents duplicate dispatch (per existing capture step 5b). Holds for all four destinations.
5. **Idempotent helper**: `validate_calendar_event.py` is pure-function; same input → same output, no side effects.
