## Subtask T015 — Gate context assembler

**Purpose**: Implement `context.py` — assembles the inputs the gate's Haiku call needs: the latest `last-tick.json`, the heartbeat contract file state, and a list of "novelty markers" (signal IDs from the tick whose threshold_status != "below").

**Steps**:
1. Create `scripts/openclaw/heartbeat_gate/__init__.py` (empty).
2. Create `scripts/openclaw/heartbeat_gate/context.py`:
   - `GateContext` dataclass: `tick_id: str`, `digest_snapshot_at_utc: str`, `signals_evaluated: list[dict]`, `issues_filed: list[dict]`, `errors: list[dict]`, `heartbeat_md_state: str` (`"empty"` or `"has_tasks"`), `novelty_markers: list[str]`.
   - `load_context(last_tick_path: Path, heartbeat_md_path: Path) -> GateContext`:
     - Reads `last_tick.json` (E3 cycle record format).

     - `novelty_markers` = `[s["signal_id"] for s in signals_evaluated if s["threshold_status"] != "below"]`.
   - `MissingTickError(Exception)` if `last_tick_path` doesn't exist.
3. Keep under ~120 lines.

## Subtask T016 — Cache-aware Haiku routing prompt

**Purpose**: Author the prompt file that the gate sends to Haiku. The system portion must be verbatim across calls (for prompt caching); the user portion carries the dynamic `GateContext`.

**Steps**:
1. Create `scripts/openclaw/heartbeat_gate/prompts/routing.prompt.md`:
   - Document structure with two clear sections:
     - **System** (verbatim, cache-hit eligible): the rule recap. Describe the three outcomes (`HEARTBEAT_OK`, `LOG_AND_SKIP`, `ESCALATE_TO_SONNET`), when to choose each, and the output JSON schema.
     - **User template** (variable): a placeholder block showing exactly what fields the assembler will inject.
   - Output schema (in the system portion):
     ```json
     {"outcome": "HEARTBEAT_OK" | "LOG_AND_SKIP" | "ESCALATE_TO_SONNET", "reason": "string ≤500 chars (required for ESCALATE)"}
     ```
   - Decision guidelines (in the system portion):
     - `HEARTBEAT_OK` when: `novelty_markers` empty AND `heartbeat_md_state == "empty"` AND no errors.
     - `LOG_AND_SKIP` when: signals look unusual but not worth waking Sonnet (e.g., low single-event counts, expected baseline noise).
     - `ESCALATE_TO_SONNET` when: ANY of — a signal tripped a threshold and filed an issue; HEARTBEAT.md has unfinished tasks needing judgment; errors require attention.
   - Document caching expectations inline: "The system portion above this line is intended for `cache_control: {type: ephemeral}` marking. Do not edit without bumping cache-buster comments."
2. The prompt should be ≥1.5K tokens in the cache-eligible system portion (caching has a minimum threshold).

**Files**:
- `scripts/openclaw/heartbeat_gate/prompts/routing.prompt.md` (new, ~150 lines / ~2K tokens)

**Validation**: human review during code review. Schema correctness validated indirectly by T021's behavioral tests.

## Subtask T017 — Anthropic SDK wrapper

**Purpose**: Implement `gate.py` — invokes the Anthropic SDK with the routing prompt, parses the 3-way response, returns a structured decision.

**Steps**:
1. Create `scripts/openclaw/heartbeat_gate/gate.py`:
   - `GateDecision` dataclass: `outcome: Literal["HEARTBEAT_OK", "LOG_AND_SKIP", "ESCALATE_TO_SONNET"]`, `reason: str`, `input_tokens: int`, `cache_hit_tokens: int`, `output_tokens: int`.
   - `GateRoutingError(Exception)` for SDK/parse failures.
   - `decide(context: GateContext, api_key_path: Path, prompt_path: Path) -> GateDecision`:
     - Load Anthropic API key from `api_key_path` (file content, stripped).
     - Load the prompt file; split on a known marker (e.g., `\n## USER TEMPLATE\n`) into system and user-template parts.
     - Build the user message by formatting the user template with `GateContext` fields (use simple `.format(**asdict(context))` or explicit replacement).
     - Invoke `anthropic.Anthropic(api_key=...).messages.create(...)` with:
       - `model="claude-haiku-4-5-20251001"`
       - `max_tokens=512`
       - `system=[{"type": "text", "text": system_text, "cache_control": {"type": "ephemeral"}}]`
       - `messages=[{"role": "user", "content": user_text}]`
     - Parse response: extract the JSON block from the text content, validate `outcome` is in the allowed enum, `reason` is a string.
     - Return `GateDecision` with token counts from `response.usage`.
   - On schema-mismatch or parse failure → raise `GateRoutingError`.
2. Retry policy: 1 retry on `anthropic.RateLimitError` or 5xx (5s backoff). After retry exhaustion → raise `GateRoutingError`.

**Files**:
- `scripts/openclaw/heartbeat_gate/gate.py` (new, ~180 lines)

**Validation**: covered by T021.

## Subtask T018 — Escalator [P]

**Purpose**: Implement `escalator.py` — invokes `openclaw system event --mode now --text "<reason>"` to wake the main agent on escalation.

**Steps**:
1. Create `scripts/openclaw/heartbeat_gate/escalator.py`:
   - `EscalationResult` dataclass: `escalated_event_id: str | None`, `error: str | None`.
   - `escalate(reason: str, timeout_seconds: int = 30) -> EscalationResult`:

## Subtask T020 — Fallback path (FR-011)

**Purpose**: When any step of the gate fails (context load, Haiku call, response parse), fall back to invoking the expensive-tier path with a "gate fallback" reason so observation is not silently dropped.

**Steps**:
1. Create `scripts/openclaw/heartbeat_gate/run.py` — the systemd entrypoint that composes all the above modules:
   - `main()` argparse: `--last-tick`, `--heartbeat-md`, `--api-key`, `--prompt`, `--last-decision`, `--ledger` (all with sane defaults).
   - Workflow:
     1. Generate `tick_id` (ULID).
     2. Try to load context. On `MissingTickError` → fallback (reason: "gate fallback — last-tick.json missing").
     3. Try to invoke gate.decide. On `GateRoutingError` → fallback (reason: "gate fallback — routing failure").
     4. If decision is `ESCALATE_TO_SONNET`:
        - Invoke `escalator.escalate(decision.reason)`.
        - Record `escalated_event_id` in the tick record.
     5. Build `GateTickRecord` (including all token counts on success path; zeros + `fallback_invoked=true` on fallback).
     6. Write the tick record via `ledger.write_tick_record`.
     7. Print SUMMARY line: `SUMMARY: outcome=<outcome> fallback=<bool> dur=<ms> tokens=in:<n>(cache:<n>)/out:<n>`.
     8. Exit 0 on any non-crash outcome (including fallback — observation succeeded even if gate failed).
   - On unexpected Python exception → write a minimal fallback `last-gate-decision.json` with `errors[]` populated, invoke escalator with "gate fallback — unhandled exception", exit 1.

**Files**:
- `scripts/openclaw/heartbeat_gate/run.py` (new, ~200 lines)

**Validation**: covered by T021 (specifically the fallback-on-failure test).
