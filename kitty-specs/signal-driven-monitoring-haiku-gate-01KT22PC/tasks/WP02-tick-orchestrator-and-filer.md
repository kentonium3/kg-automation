## Subtask T008 — Filer module

**Purpose**: Implement `filer.py` per [`contracts/filer-invocation.contract.md`](../contracts/filer-invocation.contract.md). The filer is a stateless subprocess invoker; given a signal extraction result that has tripped its threshold, it builds the title + problem-statement + observed-context tempfiles and shells out to `felix-file-issue.py`, parses the returned JSON, returns the issue number/url to the orchestrator.

**Steps**:
1. Create `scripts/openclaw/observation/filer.py`:
   - `FilingResult` dataclass: `issue_number: int | None`, `issue_url: str | None`, `error: FilingError | None`.
   - `FilingError` dataclass: `error_type: str` (one of the contract's error_type values), `error_message: str`.
   - `file_threshold_trip(signal_def: SignalDefinition, extraction: SignalExtraction, state: SignalState, now_utc: datetime) -> FilingResult`:
     - Build the title from a deterministic template (e.g., `"<human signal name> detected (<count_cycle> events in 15-min cycle, <count_rolling> in rolling hour)"`).
     - Build the problem statement: one paragraph describing the signal, count, time range, impact.
     - Build the observed context: join `extraction.excerpts` with newlines (capped at `signal_def.excerpt_lines` lines).
     - Write both as `tempfile.NamedTemporaryFile(delete=False)`; flush + close.
     - Shell out to `felix-file-issue.py` per the contract's argument schema.
     - Parse stdout for the JSON line.
     - Delete tempfiles in a `finally` block.
   - All error paths return `FilingResult(issue_number=None, issue_url=None, error=...)`. The filer never raises.
2. Use absolute path to `felix-file-issue.py` resolved relative to the repo root (find via `Path(__file__).resolve().parents[3] / "scripts/openclaw/agents/main/felix-file-issue.py"`).
3. Subprocess timeout: 60s. On timeout → `error_type = "filer_timeout"`.

**Files**:
- `scripts/openclaw/observation/filer.py` (new, ~150 lines)

**Validation**: covered by T013 unit tests.

**Purpose**: Before invoking the filer, the orchestrator must verify whether the signal's `last_filed_issue_ref` (from E2 state) still points to an OPEN issue on GitHub. If open, suppress filing; if closed (or never filed), proceed.

**Steps**:

## Subtask T010 — Tick orchestrator

**Purpose**: Implement `tick.py` — the entrypoint that runs one observation cycle: load config, load per-signal state, run each signal extractor, evaluate thresholds, file when tripped (with dedup), write last-tick.json + append ledger, emit journal SUMMARY line, exit.

**Steps**:
1. Create `scripts/openclaw/observation/tick.py`:
   - `CycleRecord` dataclass matching `data-model.md` §E3.
   - `run_cycle(config_path: Path, state_dir: Path, last_tick_path: Path, ledger_path: Path, now_utc: datetime, dry_run: bool = False, replay_log: Path | None = None) -> int` (returns exit code):
     - Generate `cycle_id` via `ulid.new()` (or stdlib-friendly equivalent — see `scripts/doc_audit/` for the existing pattern).
     - Load config via `signals.config_loader.load_config`.
     - For each enabled signal:
       - Load state via `state.load_state`.
       - Evict old rolling buckets.
       - Run the signal-specific extractor (dispatch on `signal_def.source_kind` + module name).
       - Compute `threshold_status` per the contract.
       - Save updated state (unless `dry_run`).
       - If tripped AND `not dry_run`:
         - Check existing open issue.
         - If not open → call `filer.file_threshold_trip`.
         - On success → update state's `last_filed_issue_ref` + `last_filed_at_utc`, save.
         - On failure → record in `cycle_record.errors`.
       - If tripped AND `dry_run` → record "would file" in cycle record but don't shell out.
     - Write `last_tick.json` atomically (use the `state.atomic_write` pattern from WP-01 — extract if shared).
     - Append cycle record to `ledger_path` (JSONL).
     - Print SUMMARY line to stdout: `SUMMARY: cycle=<short_id> filed=<n> skipped=<n> errors=<n> dur=<ms>`.
     - Return 0 on success, 1 on cycle-wide failure.
   - `main()` argparse: `--config`, `--state-dir`, `--last-tick`, `--ledger`, `--dry-run`, `--replay-log`. Defaults match the production paths.
2. The orchestrator runs ONE cycle per invocation — no daemon loop. Systemd invokes it on the timer.
3. `--replay-log <path>` (T012) substitutes a single static log file for the live source path resolution.
4. Keep orchestrator under ~250 lines (delegate heavy lifting to imported modules).

**Files**:
- `scripts/openclaw/observation/tick.py` (new, ~250 lines)

**Validation**: covered by T013 + T014.

**Purpose**: Substitute a static log file for the live source path resolution, enabling deterministic replay against captured fixtures (powers T014's replay integration test).

**Steps**:
