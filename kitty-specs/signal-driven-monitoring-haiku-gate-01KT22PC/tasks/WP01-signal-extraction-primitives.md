**Purpose**: Implement `signals/config_loader.py` that loads `signals/config.toml`, validates the schema in `contracts/signal-config.contract.md`, and returns a typed list of signal definitions.

**Steps**:
1. Create `scripts/openclaw/observation/signals/__init__.py` (empty marker file).
2. Create `scripts/openclaw/observation/signals/config_loader.py`:
   - Define a `SignalDefinition` dataclass matching the contract's E1 schema (signal_id, source_kind, source_path_pattern, match_pattern, match_kind, cycle_threshold, rolling_window_minutes, rolling_threshold, dedup_strategy, dedup_window_hours, priority, area_label, tier_hypothesis, excerpt_lines, enabled).

     - Validates per the contract's "Validation rules (enforced at load time)" list — duplicate signal_id is an error.
   - Define `ConfigError(Exception)` for all load-time failures.
3. Keep the module under ~150 lines.

**Purpose**: Implement `state.py` providing read/write/cold-start helpers for the per-signal state files defined in `data-model.md` §E2.

**Steps**:
1. Create `scripts/openclaw/observation/state.py`:
   - Define `SignalState` dataclass matching E2 (signal_id, cycle_id, last_cycle_count, rolling_buckets, last_event_at_utc, last_filed_issue_ref, last_filed_at_utc, last_log_position).
   - `load_state(state_dir: Path, signal_id: str) -> SignalState | None`: returns parsed state, or None if file missing (cold start).
   - `save_state(state_dir: Path, state: SignalState) -> None`: atomic write via `<path>.tmp` + `os.rename(tmp, final)`.

   - `cold_start_recovery_window_seconds() -> int`: returns the constant (4 cycles × 900s = 3600s, documented inline).
2. Use ISO 8601 with `Z` suffix consistently. Use `datetime.now(tz=timezone.utc)` — never naive.
3. Keep the module under ~150 lines.

**Files**:
- `scripts/openclaw/observation/state.py` (new, ~150 lines)

**Validation**:

## Subtask T003 — OpenClaw log helper [P]

**Purpose**: Implement `signals/openclaw_log.py` — a shared helper that tails `/tmp/openclaw/openclaw-*.log` files starting from a cursor position, yields parsed log lines, and updates the cursor.

**Steps**:
1. Create `scripts/openclaw/observation/signals/openclaw_log.py`:
   - `LogCursor` dataclass: `path: str`, `inode: int`, `byte_offset: int`, `mtime: float`.
   - `resolve_log_files(pattern: str, now_utc: datetime) -> list[Path]`: expands a glob pattern, returns paths sorted by mtime (newest last). For patterns containing `{YYYY-MM-DD}`, substitute today and yesterday's date stamps.
   - `iter_lines_since(log_path: Path, cursor: LogCursor | None) -> Iterator[tuple[dict, int]]`: opens the file, seeks to `cursor.byte_offset` if cursor.path/inode match (else cold-start from byte 0), yields `(parsed_json_dict, new_byte_offset)` per line.
   - `extract_event_time(line_dict: dict) -> datetime | None`: parses the `time` field from OpenClaw's JSON log lines.
2. Handle OpenClaw's log line format (JSON per line). Skip lines that fail to parse — emit a warning to stderr, do not raise.
3. Inode change vs cursor → log rotation. Recovery: cold-start re-read of last hour of content (caller's responsibility; helper just reports the inode change via a sentinel).
4. Keep the module under ~180 lines.

**Files**:
- `scripts/openclaw/observation/signals/openclaw_log.py` (new, ~180 lines)

**Validation**:
- [ ] `resolve_log_files` returns expected paths for a fixture directory.
- [ ] `iter_lines_since` with `cursor=None` reads from byte 0.
- [ ] `iter_lines_since` with a cursor seeks past previously-read content.
- [ ] Inode change triggers cold-start re-read (verify via fixture with two distinct files).
- [ ] Malformed JSON lines are skipped, not raised.

## Subtask T004 — Three signal extractor modules

**Purpose**: Implement one module per signal in `signals/`, each consuming the log helper from T003 and emitting `(count, representative_excerpts, last_event_at)` for the current cycle and rolling window.

**Steps**:
1. Create `scripts/openclaw/observation/signals/creds_restore.py`:
   - `extract(state_dir: Path, signal_def: SignalDefinition, now_utc: datetime) -> SignalExtraction`.
   - Uses `openclaw_log.resolve_log_files` + `iter_lines_since`.
   - Match condition: the log line's text field contains `"restored corrupted WhatsApp creds.json from backup"`.
   - Returns `SignalExtraction(count_cycle, count_rolling, excerpts, last_event_at_utc, new_cursor)`.
2. Create `scripts/openclaw/observation/signals/watchdog_reconnect.py` — same shape, matches `"web reconnect: connection closed"`.
3. Create `scripts/openclaw/observation/signals/unhandled_error.py` — same shape, matches `'"logLevelName":"ERROR"'` (literal substring).
4. Define `SignalExtraction` dataclass in `signals/__init__.py` (or a new `signals/types.py`).
5. Excerpts are the first N matching lines where N comes from `signal_def.excerpt_lines`. Redact credential material by truncating any value field longer than 64 chars to `<redacted len=N>` (per C-005). Verify the OpenClaw log format doesn't put bare credentials in `time`/`message` fields; if it does, expand the redaction list.

**Files**:
- `scripts/openclaw/observation/signals/creds_restore.py` (new, ~60 lines)
- `scripts/openclaw/observation/signals/watchdog_reconnect.py` (new, ~60 lines)
