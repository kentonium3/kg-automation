**Purpose**: Chain the new `tick.py` (signal extraction) into the existing `felix-core-digest.service`. Both `summarize.py` (existing) and `tick.py` (new) run per cycle.

   ```ini
   [Service]
   ```

## Subtask T024 — New `felix-heartbeat-gate.service` and `.timer` [P]

**Purpose**: Author the systemd user units that fire the heartbeat gate every 30 minutes.

**Steps**:
1. Create `scripts/office2/felix-heartbeat-gate.service`:
   ```ini
   [Unit]
   Description=Felix Heartbeat Gate — Haiku-tier routing for OpenClaw heartbeat
   After=network-online.target
   Wants=network-online.target

   [Service]
   Type=oneshot
   ExecStart=/usr/bin/python3 /home/claude/repos/kg-automation/scripts/openclaw/heartbeat_gate/run.py
   Environment=HOME=/home/claude
   WorkingDirectory=/home/claude/repos/kg-automation
   ```
2. Create `scripts/office2/felix-heartbeat-gate.timer`:
   ```ini
   [Unit]
   Description=Felix Heartbeat Gate — invoke routing gate every 30 minutes

   [Timer]
   OnBootSec=5min
   OnUnitActiveSec=30min
   Persistent=true

   [Install]
   WantedBy=timers.target
   ```
3. The `OnBootSec=5min` offset ensures the gate doesn't fire at the exact same moment as `felix-core-digest.timer` (which uses `OnBootSec=3min`), avoiding lockstep contention.
4. `Persistent=true` matches the existing `felix-core-digest.timer` and `felix-doc-auditor.timer` pattern — if office2 was offline for a tick, fire once on next start.

**Files**:
- `scripts/office2/felix-heartbeat-gate.service` (new, ~12 lines)
- `scripts/office2/felix-heartbeat-gate.timer` (new, ~12 lines)

**Validation**:
- [ ] Files match the existing `felix-doc-auditor.service` / `.timer` shape (grep that mission's `scripts/office2/` for the precedent).
- [ ] Cadence is 30 min (matches historical OpenClaw heartbeat).

     - Verify `kg-felix-bot` identity on office2: `ssh office2-claude 'gh auth status'` shows `kg-felix-bot` active.
     - Verify Anthropic API key file exists at `/data/services/openclaw/secrets/anthropic`.
   - **Cutover procedure** (one command per code block, per Kent's `feedback_command_formatting`):
     1. Deploy code (whatever the existing deploy-script flow is — copy from doc-auditor-driver-ops.md if applicable, OR reference the existing deploy script).

        ```bash
        ssh office2-claude 'mkdir -p /data/services/openclaw/felix-core-digest-signals/state /data/services/openclaw/felix-heartbeat-gate'
        ```
     3. Install systemd units (or trigger systemd reload after the deploy script copies them):
        ```bash
        ssh office2-claude 'systemctl --user daemon-reload'
        ```

        ```bash
        ssh office2-claude 'openclaw system heartbeat disable'
        ```

        ```bash
        ssh office2-claude 'openclaw system heartbeat last'
        ```

        ```bash
        ssh office2-claude 'systemctl --user enable --now felix-heartbeat-gate.timer'
        ```

        ```bash
        ssh office2-claude 'systemctl --user enable --now felix-core-digest.timer'
        ```

        ```bash
        ssh office2-claude 'systemctl --user start --wait felix-core-digest.service'
        ssh office2-claude 'systemctl --user start --wait felix-heartbeat-gate.service'
        ```

     - `last-gate-decision.json` shows recent decision, no errors, `fallback_invoked: false`.
     - `openclaw system heartbeat last` shows no new ticks from OpenClaw's own scheduler.
     - Both timers active in `systemctl --user list-timers`.
   - **Rollback procedure** (each step is reversible):
     1. Disable new gate timer:
        ```bash
        ssh office2-claude 'systemctl --user disable --now felix-heartbeat-gate.timer'
        ```
     2. Re-enable OpenClaw internal heartbeat:
        ```bash
        ssh office2-claude 'openclaw system heartbeat enable'
        ```
     3. (Optional) Restore service-inventory.json from git history if the new entry causes downstream consumer issues.
