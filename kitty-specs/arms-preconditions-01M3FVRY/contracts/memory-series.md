# Contract: graph-store memory series (C9)

1. **Measure**: the FalkorDB container's cgroup memory charge. It is read directly from `/sys/fs/cgroup/system.slice/docker-<full-id>.scope/memory.current` (cgroup v2, systemd driver) and includes page cache. It is recorded as `falkordb_cgroup_peak_mib` (rubric §5 @`ea3fbfc8`). It is never read via `docker stats`, and never recorded under an RSS name.
2. **Writer**: runs on the host inside `substrate.run()` for a harness run only. It starts before the runner, waits (bounded) for its first reading, and fails closed with a named error if none arrives. It is stopped in `finally`. The container id is resolved by `docker inspect` once.
3. **Interval**: the real interval is written in the series header and carried to the run record. Every freshness tolerance is a multiple of that recorded interval (stale > 5 intervals, gap > 5 intervals, where exactly 5 is allowed).
4. **Generations**: each `substrate.run` writes its OWN series file, `RUNS_DIR/falkordb-cgroup-<series_id>.jsonl`, opened exclusively and never truncated or reused. Before any graph activity, the harness records a `series_generation` ledger event `{series_id, path, container_id, interval_s, started_ts}`, which binds the generation to its expected container DURABLY. Reconstruction checks every file against its recorded descriptor, never against the current environment.
5. **Reader**: an explicit HISTORICAL-window evaluator (it reuses the sample-and-hold reconstruction of rubric §5) is called by summary and export over [start, end] windows derived from ledger boundary events. The per-attempt graph-store sampler path in the harness is REMOVED: today it is entered per attempt, refuses unreadable data, and attaches its peak to G rows (`run_849_harness.py` ~L543, L551, L655).
7. **Per-question report (§5 @`a00abc03`)**: reconstructed POST HOC from durable boundary events and untruncated per-generation series files, over [build start .. last graph query]. It is a container high-water mark that is NOT attributable to the question. The run also reports the baseline and the all-resident total. A window that crosses a series generation reports `could_not_check: interrupted`. Per-cell rows carry no graph-store column.
8. **Two sampler roles, two failure modes.** The ceiling guard's live sampler unreadable at send refuses the cell (safety). The graph-store figure unavailable is `could_not_check` in the report, and the cell is UNAFFECTED (a reported column, about 0.4 % of the ceiling). A missing graph-store figure must never refuse a cell.
6. **Fail closed, without affecting cells**: an absent, stale, gapped, wrong-container or interrupted series makes the reconstructed graph-store figure `could_not_check` with a reason. It is never a zero, never a pass, and never refuses a cell. Cell refusal on an unreadable sampler belongs to the ceiling guard only (item 8).
