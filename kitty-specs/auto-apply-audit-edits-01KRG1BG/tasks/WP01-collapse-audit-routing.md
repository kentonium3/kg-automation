# WP01 — Implement handle_audit_routing.py and collapse § 7.9/§ 7.10/§ 7.11

## Objective

Add the felix-doc-auditor orchestrator helper that handles all forward-path audit decision logic (partition by change_type, auto-apply known classes via atomic mode-preserving writes, file pending-approval for any gated subset, post audit summary on originating issue). Update AGENTS.md so the auditor's prompt reads "if any edit proposals, run helper, done" — collapsing three prose sections into a single CLI invocation.

**Note on AGENTS.md.tmpl**: felix-doc-auditor does NOT have an AGENTS.md.tmpl (unlike felix-admin-capture). T005 in the subtask list is a no-op verification subtask — it exists to preserve the frontmatter `subtasks` contract; the implementer's task is simply to confirm via `ls scripts/openclaw/agents/felix-doc-auditor/` that no .tmpl mirror is needed.

**Review scope (WP01)**: T001–T005 — new helper + tests + AGENTS.md edits + local pytest pass. Deploy and end-to-end verification (next cron tick, SC-001 + SC-004) are post-merge operator scope (same discipline as missions #33 and #34).

## Context

#259 documented the over-gating bug: felix-doc-auditor routes every edit-bearing audit through the Level-1 approval gate, regardless of whether the proposed edit is a deterministic mechanical fix (`frontmatter_date` etc.) or a judgment-required content change. Per Kent's framing: every current `change_type` is by definition a deterministic-known-fix surface — if the auditor detected the drift, it already knows the correct value. Cases requiring judgment already route to `docs-debt` issues via § 7.8 (autonomous, no gate).

This WP applies the deterministic-work-into-scripts principle (memory `feedback_scripts_vs_llm.md`) one level deeper: not just moving the routing decision into a script, but consolidating the full audit-decision orchestration (route → commit → gate-file → summary-post) into one helper. Three prose sections of AGENTS.md collapse to one CLI invocation.

The mission also reuses the atomic-write pattern landed by #254 (mission #33) to ensure the auditor's edit-application surface doesn't re-introduce the perm-orphan bug.

See [spec.md](../spec.md), [plan.md](../plan.md), [research.md](../research.md), and [quickstart.md](../quickstart.md) for full context.

### T001 — Create `scripts/openclaw/agents/felix-doc-auditor/handle_audit_routing.py`

**Purpose**: Single helper that does forward-path audit decision orchestration.

**CLI**:

```
python3 handle_audit_routing.py @/path/to/audit-state.json
```

**Input JSON shape** (document at the top of the script as the contract):

```json
{
  "audit_issue_number": 258,
  "commit_sha": "7471fe7",
  "areas": ["area/biz-ops", "area/felix-core"],
  "proposals": [
    {
      "doc_path": "docs/INDEX.md",
      "change_type": "frontmatter_date",
      "current_value": "2026-05-10",
      "proposed_value": "2026-05-13",
      "evidence_source": "commit 7471fe7 (2026-05-13)",
      "confidence": "high"
    }
  ],
  "debt_issues_filed": [],
  "missing_artifact_issues_filed": []
}
```

**Steps**:

1. Module-level constant — the auto-apply allowlist (C-001 / Decision 1):

   ```python
   AUTO_APPLY_CHANGE_TYPES = frozenset({
       "frontmatter_date",
       "version_bump",
       "path_rename",
       "dead_ref_removal",
       "registry_entry_add",
       "registry_autonomy_update",
   })
   ```

2. Argument parsing — accept a single positional argument; if it starts with `@`, treat the remainder as a path; else treat the string itself as a path.

3. Load + validate JSON. Missing required keys → exit non-zero with structured stderr identifying what was missing.

4. Partition `proposals` by `change_type`:
   - In allowlist → `auto_apply` list
   - Else → `gated` list

5. For each `auto_apply` proposal: apply the edit via atomic mode-preserving write. Inline the #254 pattern with a comment cross-referencing `scripts/inbox/inject_parse_error_marker.py`:

   ```python
   def _atomic_write(path: Path, content: str) -> None:
       """Atomic write that preserves the original file's mode.

       Mirror of the pattern landed by mission #33 (#254) in
       scripts/inbox/inject_parse_error_marker.py. Mode preservation is
       load-bearing because the doc-auditor edits files that may be
       cross-user (e.g., kgale-owned docs edited by the claude-running
       agent); without it, ob (Obsidian Sync) loses read access.
       """
       parent = path.parent
       fd, tmp_name = tempfile.mkstemp(prefix=path.name + ".", suffix=".tmp", dir=str(parent))
       try:
           with os.fdopen(fd, "w", encoding="utf-8") as fh:
               fh.write(content)
           try:
               mode = stat.S_IMODE(os.stat(path).st_mode)
               kind = "preserved"
           except FileNotFoundError:
               mode = 0o664
               kind = "new"
           os.chmod(tmp_name, mode)
           os.replace(tmp_name, path)
           print(f"INFO: atomic_write {path} mode={oct(mode)} ({kind})", file=sys.stderr)
       except Exception:
           try:
               os.unlink(tmp_name)
           except OSError:
               pass
           raise
   ```

   Apply each auto-apply proposal: read the doc, perform the substitution (the change_type determines the substitution semantics — e.g., `frontmatter_date` replaces the value of a specific frontmatter key on a specific line). Write atomically.

   The detailed substitution semantics per change_type are encoded in helper functions:
   - `_apply_frontmatter_date(content, proposal)` — replace the YAML frontmatter date field
   - `_apply_version_bump(content, proposal)` — replace a version string
   - `_apply_path_rename(content, proposal)` — replace path occurrences
   - `_apply_dead_ref_removal(content, proposal)` — remove a reference
   - `_apply_registry_entry_add(content, proposal)` — add an entry to a registry
   - `_apply_registry_autonomy_update(content, proposal)` — update an autonomy designation

   Each helper receives the current file content + the proposal record and returns the new content. If a helper cannot apply the proposal (e.g., the `current_value` doesn't match what's actually in the file — likely indicates concurrent drift), it raises `RouteApplyError(proposal, reason)` which the main flow catches and reports.

6. If any auto-applies succeeded: build a structured `git commit` message and run `git commit` via subprocess. Example commit body:

   ```
   docs(audit): apply <N> auto-resolved edits from audit #<M>

   Triggered by commit <SHA>. Auto-applied per the felix-doc-auditor
   change_type allowlist (frontmatter_date, version_bump, etc.).

   Applied edits:
   - <path>: <change_type> (<current> → <proposed>)
   - <path>: <change_type> (<current> → <proposed>)
   ```

7. If `gated` is non-empty: build the pending-approval issue body using the existing template (`kitty-specs/felix-doc-auditor-agent-01KR7JK9/contracts/audit-pending-approval-issue.template.md`). Run `gh issue create` via subprocess. Capture the new issue number from output.

8. Post the audit summary comment on the originating audit issue (`audit_issue_number`) via `gh issue comment`. The summary lists applied edits, gated edits (with link to new pending-approval issue if filed), and references to debt/missing-artifact issues from § 7.8 already-filed (passed in via the JSON).

9. Close the originating audit issue if all applied (or there were no gated edits). Else, leave it open (the pending-approval issue is the new gate).

10. Exit codes:
    - 0: full success
    - 1: input validation failure (malformed JSON, missing keys)
    - 2: apply failure (one or more edits couldn't be applied — DO NOT commit partial work; rollback the staged changes via `git checkout -- <files>`)
    - 3: commit failure (git commit non-zero)
    - 4: gate-file failure (`gh issue create` failed AFTER commit succeeded — leaves system in a weird state; structured stderr identifies which)
    - 5: summary-post failure (everything else succeeded but `gh issue comment` failed — non-fatal; system is in correct state, just under-reported)

**Files**:
- `scripts/openclaw/agents/felix-doc-auditor/handle_audit_routing.py` (new, ~250–320 lines)

**Validation**:
- [ ] Module-level constant `AUTO_APPLY_CHANGE_TYPES` contains all 6 current change_types.
- [ ] `_atomic_write` references `stat.S_IMODE`, `os.stat`, `os.chmod` and preserves mode (matching #254 helpers).
- [ ] All six `_apply_*` substitution helpers exist (one per known change_type).
- [ ] Commit + gate-file + summary-post are sequenced correctly: gate-file only after commit succeeds; summary-post is last.
- [ ] Structured error reporting on each failure mode (exit codes 1-5 with stderr identifying which leg).

**Edge cases**:
- Empty `proposals` list → exit 0 immediately, no operations.
- All in `gated`, none in `auto_apply` → skip git commit; file gate; post summary; exit 0.
- All in `auto_apply`, none in `gated` → apply, commit, no gate, post summary, close audit issue, exit 0.
- Mixed → apply auto-apply, commit, file gate for gated, post summary (does NOT close audit issue — the gate is now the open thread), exit 0.
- `current_value` mismatch on apply → exit 2 with that proposal identified; no partial commit.

### T002 — Create `tests/openclaw/agents/felix-doc-auditor/test_handle_audit_routing.py` [P]

**Purpose**: Unit-test the handler end-to-end via `subprocess.run`, with mocks for git/gh subprocess calls and tmp_path fixtures for file operations.

**Approach**:

- Drive the handler via `subprocess.run(["python3", str(HANDLER_PATH), f"@{tmpfile}"])` for full CLI surface coverage.
- For the *handler's internal* `subprocess.run` calls (to `git commit` and `gh issue create`), use a thin shim: have the handler accept a `--git-bin` and `--gh-bin` flag (or `GIT_BIN` / `GH_BIN` env vars) that default to `git` / `gh`. In tests, point them at small `tmp_path` stub scripts that record their invocations and emit canned outputs. Cleaner than `monkeypatch` for subprocess (subprocess invocation crosses Python process boundary).

**Test cases** (per plan.md test plan):

1. **`test_all_auto_apply_no_gate`**: 1 `frontmatter_date` proposal on a `tmp_path/doc.md` with mode 0o644. Run handler. Expect: file updated with new value, mode preserved (0o644), git stub recorded one commit invocation, no gh stub invocation for issue create, gh stub recorded one issue comment (summary), exit 0.

2. **`test_all_gated`**: 1 fabricated proposal with `change_type: "prose_replacement"` (not in allowlist). Expect: no file edit, no git commit, gh stub recorded one issue create (for gate), gh stub recorded one issue comment (for summary), exit 0.

3. **`test_mixed_partition`**: 1 `frontmatter_date` + 1 unknown. Expect: file edited (known), git commit invoked for it, gh issue create invoked for gate (with body listing only the unknown), gh issue comment summary names both partitions, exit 0.

4. **`test_empty_proposals`**: `proposals: []`. Expect: no git/gh activity, no file edits, exit 0.

5. **`test_invalid_json`**: file contains malformed JSON (e.g., `{not valid`). Expect: exit code 1, structured stderr, no git/gh calls.

6. **`test_commit_failure_propagates`**: git stub returns non-zero. Expect: exit code 3, gate NOT filed (even if there's a gated subset — don't half-do), no summary posted, stderr identifies commit failure.

7. **`test_atomic_write_preserves_mode`** (regression guard against re-introducing #254): pre-create doc at mode 0o644 with valid frontmatter; apply one `frontmatter_date` proposal. Verify post-write `stat().st_mode & 0o777 == 0o644`. Also test 0o600 and 0o664.

8. **`test_apply_mismatch_aborts`** (edge case from T001): proposal's `current_value` doesn't match what's in the file. Expect: exit code 2 with proposal identified, no commit, no gate file.
