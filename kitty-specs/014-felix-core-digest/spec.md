# Felix Core Digest

**Feature**: 014-felix-core-digest
**Mission**: software-dev
**Status**: draft
**Created**: 2026-04-04

---

## Overview

Every Felix agent logs every action it takes, and a centralized intelligence
layer reads those logs to produce a consolidated daily digest visible in
Obsidian. Today this pipeline is broken: agents write free-form Markdown with
no enforced schema, the observation module (`summarize.py`) parses that
Markdown with fragile regex, and the entire pipeline has never been deployed.

Felix Core Digest replaces this architecture with a deterministic boundary:
a Python log writer (`log_action.py`) that receives structured arguments from
agents and owns all schema enforcement, JSONL serialization, and file I/O.
`summarize.py` is rewritten to parse JSONL instead of Markdown, deployed on
a 15-minute cron on office2, and writes human-readable digest notes to
per-agent subdirectories in the Obsidian vault.

The architectural intent: deterministic Python owns file I/O and schema
enforcement; agents own only the judgment of what to log. Raw logs are JSONL
(machine consumption); digest notes are Markdown (human consumption in
Obsidian). `summarize.py` is the translation layer between them.

## Actors

| Actor | Description |
|---|---|
| **Felix Agent** | Any deployed Claude agent (felix-admin-tasker, felix-admin-capture, felix-admin-habits) that produces actions to log |
| **log_action.py** | Deterministic Python utility that receives structured arguments and writes schema-valid JSONL entries |
| **summarize.py** | Scheduled Python service that reads JSONL logs and produces human-readable Markdown digests |
| **Kent** | System owner who reads digest notes in Obsidian and monitors agent activity |
| **office2** | Always-on Ubuntu server hosting the scheduled summarize.py execution |

## User Scenarios & Testing

### Scenario 1: Agent Logs an Action

**Given** a Felix agent completes an action during a run
**When** the agent calls `log_action.py` with structured arguments (agent name, category, action, target, outcome)
**Then** a valid JSONL entry is appended to `~/second-brain/agents/logs/{agent-name}/YYYY-MM-DD.jsonl`
**And** the agent subdirectory is created if it does not exist
**And** the entry includes a timestamp and run_id generated by log_action.py

### Scenario 2: Invalid Log Call Rejected

**Given** an agent calls `log_action.py` with a missing required field or invalid category
**When** log_action.py validates the input
**Then** log_action.py exits with a non-zero status and a clear error message
**And** no partial or malformed entry is written to the log file

### Scenario 3: Digest Generation on Schedule

**Given** agents have written JSONL log entries during the day
**When** the 15-minute cron fires and runs `summarize.py`
**Then** summarize.py reads all agent JSONL files for the current day
**And** writes per-agent Markdown digest files to `{vault_path}/Agent-Logs/{agent-name}/YYYY-MM-DD-log.md`
**And** writes a consolidated `overview.md` at `{vault_path}/Agent-Logs/overview.md`
**And** Kent sees the digest notes in Obsidian within 15 minutes of an agent run

### Scenario 4: Idle System Produces No Writes

**Given** no new JSONL entries exist since the last summarize.py run
**When** the 15-minute cron fires
**Then** summarize.py detects no new content and skips file writes
**And** no unnecessary file modifications occur in the vault

### Scenario 5: Retention Cleanup

**Given** per-agent digest directories contain files older than 5 calendar days
**When** summarize.py runs and writes today's digest
**Then** files with date-stamped names older than 5 days are deleted from each agent subdirectory
**And** age is determined by parsing filenames, not filesystem mtime

### Scenario 6: Verbosity Controls Log Detail

**Given** an agent's `log_verbosity` is set to "brief" in agent-registry.json
**When** the agent calls `log_action.py`
**Then** only required fields are written (no context or trace blocks)

**Given** an agent's `log_verbosity` is set to "standard"
**When** the agent calls `log_action.py` with context data
**Then** required fields plus the context block are written

**Given** an agent's `log_verbosity` is set to "verbose"
**When** the agent calls `log_action.py` with context and trace data
**Then** all blocks (required, context, trace) are written

### Scenario 7: Malformed JSONL Line Handling

**Given** a JSONL log file contains a malformed line (invalid JSON or missing required fields)
**When** summarize.py parses the file
**Then** the malformed line is logged to stderr and skipped
**And** all valid entries in the file are processed normally
**And** summarize.py does not crash

### Scenario 8: Generative Output Cross-Reference

**Given** an agent produces stochastic output (a task proposal, a drafted message)
**When** the agent logs the action via `log_action.py`
**Then** the log entry contains a cross-reference (e.g., `proposal_ref`) rather than the full generated text
**And** any string field value exceeding 120 characters is truncated with `[truncated]` appended

## Functional Requirements

| ID | Requirement | Status |
|---|---|---|
| FR-01 | `log_action.py` accepts structured arguments from agents and writes a single valid JSONL entry to `~/second-brain/agents/logs/{agent-name}/YYYY-MM-DD.jsonl` | Proposed |
| FR-02 | `log_action.py` creates the agent subdirectory on first write; multiple runs per day append to the same file | Proposed |
| FR-03 | `log_action.py` fast-fails with a non-zero exit code and clear error message when required fields are missing or category values are invalid | Proposed |
| FR-04 | `log_action.py` generates and writes `ts` (UTC ISO-8601) and `run_id` (`{agent}-{YYYYMMDD}-{HHMM}`) for every entry; agents never supply these | Proposed |
| FR-05 | `log_action.py` enforces a maximum of 120 characters on any string field value and appends `[truncated]` when exceeded | Proposed |
| FR-06 | `log_action.py` reads the agent's `log_verbosity` from `agent-registry.json` via `config.py` and writes only the blocks appropriate to that level: brief (required only), standard (required + context), verbose (required + context + trace) | Proposed |
| FR-07 | Valid category values are limited to: `routine`, `flagged`, `error`, `security` | Proposed |
| FR-08 | `summarize.py` replaces all Markdown regex parsing (`CATEGORY_PATTERN`, `AGENT_PATTERN`, `RUN_TIME_PATTERN`, `SUMMARY_LINE_PATTERN`, `parse_log_file()`) with JSONL parsing via a new `parse_jsonl_log(path)` function | Proposed |
| FR-09 | `summarize.py` walks per-agent subdirectories to locate `YYYY-MM-DD.jsonl` files (replaces flat directory scan) | Proposed |
| FR-10 | `summarize.py` writes per-agent Markdown digest files to `{vault_path}/Agent-Logs/{agent-name}/YYYY-MM-DD-log.md` and a consolidated `overview.md` at `{vault_path}/Agent-Logs/overview.md` | Proposed |
| FR-11 | `summarize.py` enforces 5-day retention: after writing today's digest, deletes files in each agent subdirectory with date-stamped names older than 5 calendar days (age from filename, not mtime) | Proposed |
| FR-12 | `summarize.py` is idempotent on idle: skips file writes when no new JSONL entries exist since the last run | Proposed |
| FR-13 | Malformed JSONL lines are logged to stderr and skipped; they do not halt the summarize.py run | Proposed |
| FR-14 | All existing `summarize.py` test fixtures are rewritten as JSONL; each existing Markdown fixture is mapped to its JSONL equivalent before deletion | Proposed |
| FR-15 | New test fixtures cover: multi-run days, verbose entries with trace fields, malformed line handling, and truncated generative output cross-references | Proposed |
| FR-16 | All three deployed agents' AGENTS.md Action Logging sections are updated to reference `log_action.py` (or constrained JSONL fallback); every previously-recorded field is mapped to a `log_action.py` argument with no data silently dropped | Proposed |
| FR-17 | Per-agent action type and category lists are documented in each agent's AGENTS.md | Proposed |
| FR-18 | `log_verbosity` field is added to each agent entry in `agent-registry.json`; all deployed agents start at `"standard"` | Proposed |
| FR-19 | `config.py` exposes a `log_verbosity(agent_name)` method following the exact pattern of `autonomy_level()` | Proposed |
| FR-20 | `agents/logs/` is added to the second-brain repo `.gitignore` | Proposed |
| FR-21 | A scheduled trigger (systemd timer or cron) is deployed on office2 that runs `summarize.py` every 15 minutes under the `claude` service account, surviving reboots | Proposed |
| FR-22 | `docs/handbooks/observation-ops.md` is created covering: reading digests in Obsidian, accessing raw JSONL on office2, changing verbosity, verifying the trigger, running summarize.py manually with `--dry-run`, troubleshooting, and fallback architecture implications | Proposed |
| FR-23 | `scripts/deploy/deploy-f014.sh` is created following the F013 pattern: copies updated AGENTS.md files to office2, deploys `log_action.py`, and installs the summarize.py systemd timer | Proposed |
| FR-24 | Architecture documentation is updated: `service-inventory.json` adds felix-core-digest as `type: "cron"` with `updated_by: "F014"`; `data-flows.json` adds the agent-to-digest data flow; markdown counterparts updated to match | Proposed |

## Non-Functional Requirements

| ID | Requirement | Threshold | Status |
|---|---|---|---|
| NFR-01 | `log_action.py` must complete a single log write in under 100ms on office2 hardware | < 100ms per write | Proposed |
| NFR-02 | `summarize.py` must process a full day's logs for all agents in under 10 seconds | < 10s for daily digest generation | Proposed |
| NFR-03 | JSONL log entries must be append-only; no existing entries are modified or deleted by `log_action.py` | Zero mutations of existing entries | Proposed |
| NFR-04 | `log_action.py` must not import any packages beyond the Python standard library | Zero external dependencies | Proposed |
| NFR-05 | All new and modified code must have test coverage validated by the existing test framework | Tests pass before deployment | Proposed |

## Constraints

| ID | Constraint | Status |
|---|---|---|
| C-01 | Agents determine what to log (stochastic judgment); `log_action.py` owns how it is written (deterministic enforcement) — this boundary must not be blurred | Active |
| C-02 | Raw logs are JSONL; digest notes are Markdown — format matches consumer | Active |
| C-03 | `log_action.py` is a utility script; it is not a deployed service and does not appear in `service-inventory.json` or `AGENT-REGISTRY.md` | Active |
| C-04 | felix-core-digest is registered in `service-inventory.json` as `type: "cron"`, not in `AGENT-REGISTRY.md` — the registry is reserved for Claude agents with governance concerns | Active |
| C-05 | The `claude` service account on office2 does not have sudo access; deployment must not require elevated privileges | Active |
| C-06 | `~/second-brain/notes/02-Growth/_private/` is never read, written, referenced, or logged under any circumstance | Active |
| C-07 | Digest output writes to `{vault_path}/Agent-Logs/`; the old path `00-System/agent-activity/` is left untouched | Active |
| C-08 | The planning phase must research whether OpenClaw supports agents calling external Python scripts and document the finding before any code is written — this determines primary vs. fallback log path | Active |
| C-09 | If OpenClaw does not support subprocess calls, the constrained JSONL fallback is a legitimate operating mode with identical schema; enforcement shifts from code to agent instruction | Active |
| C-10 | Deploy script follows the established per-feature pattern at `scripts/deploy/deploy-f{NNN}.sh` using scp/ssh to `office2-claude` | Active |

## Success Criteria

1. An agent action produces a schema-valid JSONL entry in the correct per-agent log file within the same run
2. `summarize.py` generates accurate, human-readable Markdown digests from JSONL input with no Markdown-regex parsing remaining
3. Digest notes appear in Obsidian on Kent's Mac within 15 minutes of an agent run on office2
4. The system is idle-safe: no file writes occur when no new agent activity exists
5. Digest files older than 5 days are automatically removed
6. Verbosity level controls log detail per-agent without code changes (registry configuration only)
7. All existing summarize.py tests pass against JSONL fixtures
8. Operations runbook enables Kent to monitor, troubleshoot, and adjust the system without reading code
9. Architecture documentation accurately reflects the deployed state

## Key Entities

| Entity | Description |
|---|---|
| **JSONL Log Entry** | A single-line JSON object conforming to the FR-01 schema; the atomic unit of agent activity data |
| **Log File** | A daily JSONL file at `~/second-brain/agents/logs/{agent-name}/YYYY-MM-DD.jsonl` containing all entries for one agent on one day |
| **Digest File** | A per-agent daily Markdown file at `{vault_path}/Agent-Logs/{agent-name}/YYYY-MM-DD-log.md` summarizing that agent's activity |
| **Overview** | A consolidated Markdown file at `{vault_path}/Agent-Logs/overview.md` regenerated on each summarize.py run |
| **Agent Registry** | `agent-registry.json` — source of truth for per-agent configuration including `log_verbosity` and `autonomy_level` |

## Assumptions

1. The existing `summarize.py` digest generation logic (formatting, multi-run consolidation) is correct and only the input parsing layer changes
2. Obsidian vault sync from office2 to Mac is operational (existing infrastructure)
3. The `claude` user on office2 has write access to `~/second-brain/agents/logs/` and the vault digest output path
4. systemd user timers (or crontab) are available to the `claude` user on office2 without sudo
5. All three deployed agents (felix-admin-tasker, felix-admin-capture, felix-admin-habits) are the complete set of agents requiring AGENTS.md updates

## Out of Scope

- WhatsApp critical alert delivery (send stub remains; activation deferred until DM policy is re-enabled)
- Escalation engine (deferred to F015)
- Daily briefing (F017 — consumes digest output; this spec produces it)
- Security agent or adversarial monitoring (Core Hub / D06 scope)
- New agent behavior changes (F014 changes how agents log, not what they do)
- Migration or cleanup of old output path `00-System/agent-activity/`

|---|---|---|---|
| OpenClaw does not support subprocess calls from agents | Medium | High | Constrained JSONL fallback defined with identical schema (C-09); research is first planning step (C-08) |
| JSONL fixture rewrite introduces test coverage gaps | Low | Medium | Planning phase maps every existing fixture to JSONL equivalent before deleting any Markdown file |
