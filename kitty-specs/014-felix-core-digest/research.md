## R1: Can OpenClaw Agents Call External Python Scripts?

**Decision**: Yes — primary path (log_action.py CLI) is viable.

**Rationale**: OpenClaw provides an `exec` tool that agents use to run shell
commands. This is documented extensively in deployed skills:

- `vikunja-api/SKILL.md`: "using curl via the `exec` tool"
- `whisper/SKILL.md`: "Use the `exec` tool to run these curl commands"
- `openclaw-capabilities.md` (RQ-4): Three-gate autonomy model with
  configurable exec tool policies (always-ask, on-miss, unrestricted)

All deployed agents already use the exec tool for Vikunja API calls via curl.
Calling `python log_action.py --agent ... --category ...` follows the same
pattern. No fallback path needed, though the constrained JSONL fallback
remains documented for robustness.

**Alternatives considered**:
- Constrained JSONL direct-write (fallback): Viable but loses deterministic
  enforcement. Not needed given exec tool availability.

## R2: Existing summarize.py Architecture

**Decision**: Rewrite parsing layer only; preserve digest generation logic.

**Rationale**: The existing `summarize.py` has a clean separation between:
1. **Parsing layer** (to be replaced): `CATEGORY_PATTERN`, `AGENT_PATTERN`,
   `RUN_TIME_PATTERN`, `SUMMARY_LINE_PATTERN` regexes and `parse_log_file()`
   state machine
2. **Processing layer** (to preserve): `filter_actions_by_autonomy()`,
   `detect_critical_alerts()`, `summarize_routine_actions()`
3. **Output layer** (to modify): `generate_digest()`, `generate_agent_detail()`,
   `run()` — output paths and retention logic change

The processing layer operates on dicts with `{category, text}` structure.
The new `parse_jsonl_log()` function must return compatible dicts so the
processing layer requires minimal changes.

**Key change**: `find_log_files()` currently globs a flat directory for
`*{date}*` pattern. Must be rewritten to walk per-agent subdirectories and
match `YYYY-MM-DD.jsonl` files.

## R6: Office2 Scheduling Pattern

**Decision**: Use systemd user timer under `claude` account, replicating
`second-brain-sync.timer` interval pattern.

**Rationale**: `second-brain-sync.timer` already runs every 15 minutes with:
- `OnBootSec=2min` (delay after boot)
- `OnUnitActiveSec=15min` (repeat interval)
- `Persistent=true` (catch up if system was down)
- User-level timer (no sudo required)

This is the exact pattern needed for felix-core-digest. The timer runs
under the `claude` user account (not kgale).

**Note**: The vault-snapshot.timer uses calendar-based scheduling (daily at
2AM) — wrong pattern for 15-minute intervals.

**Alternatives considered**:
- OpenClaw cron: Used by F013 for agent scheduling, but summarize.py is
  not an OpenClaw agent — it's a Python script. systemd timer is correct.
- crontab: Works but systemd timers provide persistent scheduling, better
  logging (journalctl), and are the established pattern on office2.

## R7: Second-Brain .gitignore

**Decision**: Add `agents/logs/` to `.gitignore`.

**Current state**: The second-brain `.gitignore` excludes `notes/` (managed
by Obsidian Sync) but does NOT exclude `agents/logs/`. Raw JSONL logs would
be committed on `git add .` via the 15-minute second-brain-sync timer.

**Action**: Add `agents/logs/` entry. This prevents raw JSONL from entering
git while digest Markdown (written to `notes/` path under `Agent-Logs/`)
is also excluded by the existing `notes/` rule — digests flow through
Obsidian Sync, not git.

## R8: Deploy Script Pattern

**Decision**: Follow F013 deploy-f013.sh pattern exactly.

**F013 pattern summary**:
- `set -euo pipefail` strict mode
- `REPO_ROOT` relative path resolution
- Staged deployment with progress messages
- `scp` for file transfer to `office2-claude`
- `ssh office2-claude` for remote commands (directory creation, service restart)
- OpenClaw CLI integration for agent workspace deployment
- Built-in validation and manual verification checklist

**F014 deploy stages**:
1. Copy `log_action.py` to observation module on office2
2. Copy updated AGENTS.md files to agent workspace paths
3. Copy systemd timer/service units
4. Enable and start the timer (user-level, no sudo)
5. Validate: confirm timer is active, run summarize.py --dry-run

## R9: Digest Output Path and Obsidian Sync

**Decision**: Write to `~/second-brain/notes/Agent-Logs/`. Digests reach
Kent's Mac via Obsidian Sync (not git).

**Rationale**: The `notes/` directory is excluded from git (`.gitignore`
entry: `notes/`). Content under `notes/` is synced by Obsidian Sync, which
runs continuously on office2 via `obsidian-sync.service`. Digest Markdown
files written to `notes/Agent-Logs/` will appear in Obsidian on all
devices within seconds of the sync cycle.

**No migration**: Old path `notes/00-System/agent-activity/` is left
untouched per Kent's direction.
