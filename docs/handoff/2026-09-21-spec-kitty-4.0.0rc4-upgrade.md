## The one idea that matters: builds, not version strings

spec-kitty does not yet report version + build together. During pre-release QA the version
string identifies nothing — `main` declared `4.0.0rc4` for days with no rc4 tag and no PyPI
artifact, so "wait for rc4 on PyPI" would have blocked indefinitely. Resolve a wanted
version to a **commit**, pin the full SHA, and report what was installed by SHA.

```bash
git ls-remote --tags https://github.com/spec-kitty/spec-kitty.git   # tagged builds
git ls-remote https://github.com/spec-kitty/spec-kitty.git HEAD     # main HEAD
gh api repos/spec-kitty/spec-kitty/contents/pyproject.toml --jq '.content' | base64 -d | grep -E '^version'
```

Build IDs in play: 3.2.7 = `fb4e8fa98` · 4.0.0rc3 = `fbe1109fa` · rc4 candidate = `619bd1137`.

## Traps that cost time here

**`spec-kitty upgrade`'s exit code is not a health signal (#992).** It returns 1 even when
it prints `Project is already up to date!`, because `--yes` fails to suppress a Team Kitty
prompt and a declined optional remediation fails the whole command. Verify convergence with
`pending_migrations: []` and `doctor tool-surfaces` exit 0 instead.

**`upgrade` needs up to three invocations (#993).** The first aborts on
`_recheck_command_completion` having already partially applied — version stamp advanced,
manifests modified, drift outstanding. "Upgrade failed" does not mean nothing changed.

**`upgrade --dry-run` always claims 184 outstanding repairs on Windows (#994).** Those are
`chmod` effects that cannot converge because `os.chmod` can't set POSIX modes on Windows.
Cosmetic; ignore the count.

**`.kittify/migrations/` is gitignored (#996).** The mission-state run manifest and the 20
quarantined rows live only in the working tree. `git clean -xfd` destroys them. Copies are
in the out-of-tree backup.

**`docs/temp/` is gitignored** (`.gitignore:35`, `temp/`). A findings copy sits there for a
bot running against this working tree, but it will never push. Any agent reading from a
clone, office2, or the QA Windows account must read
`docs/diagnostics/spec-kitty-4.0.0rc4-upgrade-findings.md` — the canonical, pushed version.

**`.kittify/` and `kitty-specs/` are spec-kitty-owned.** When merge conflicts hit generated
manifests, do not hand-resolve — take either side to clear the tree, then re-run
`spec-kitty upgrade` so the CLI regenerates them authoritatively. That is how `331d46fd`
was produced.
